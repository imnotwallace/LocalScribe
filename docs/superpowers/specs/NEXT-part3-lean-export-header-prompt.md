## What Part 3 does

Cut the exported transcript header from ~22 possible lines to seven. The owner's words: *"Half the metadata in the exported transcript is useless."*

**Keep:** title, `Date`, `Matter(s)`, `Speakers heard`, `Medium`, `Source` (imports only — see below), `Description?`, the in-progress notice, the excerpt line + notice, the opt-in assistant summary, the disclaimer.

**Remove:** `App`, `Participants`, `Session ID`, `Exported`, `Transcript version` (which carries the model name and backend), `Weights file`, `Model accuracy`, `Audio SHA-256`, `Transcript SHA-256`, every per-leg `Audio SHA-256`, `Human edits`.

**Also delete outright:** the per-turn `" [text corrected]"` mark, `ExportOptions.MarkCorrectedTurns`, `ExportSetting.MarkCorrectedTurns`, the `ExportDialogViewModel` property and the XAML binding.

## Owner decisions — settled, do not re-litigate

1. **`Speakers heard` replaces `Participants`.** Derived from the rows, so it cannot drift from the body. A silent attendee disappearing from the document is accepted.
2. **`Source:` renders for IMPORTS ONLY.** A recorded call has no source file — its legs are the hardcoded constants `local.flac`/`remote.flac` (`StoragePaths.cs:72-77`), so printing them tells a reader nothing. Recorded sessions simply have no `Source` line, the way a session with no matter has no `Matter` line.
3. **Human-edit disclosure moves into the disclaimer as prose**, in two variants so it never overclaims:
   - untouched: *"This transcript was generated by automated speech recognition and may contain errors. It is not a certified record."*
   - edited: *"This transcript was generated by automated speech recognition and reviewed and corrected by a person. It may contain errors and is not a certified record."*
   Choose the variant from the human-layer counts already computed.
4. **Suppressed duplicates print only when non-zero**, as `Omitted: N duplicate turns (echo)`. This is a machine omission, not a human act, so the disclaimer does not cover it — and it is the one count the spec says would read as concealment if hidden. Silent on single-leg imports.
5. **Technical provenance is not lost, it moves.** The `.zip` bundle is a verbatim folder copy (`SessionArchiver.cs:18-48`), so `session.json`, `meta.json` and `manifest.json` still carry model, backend, weights file and every hash. `Verify integrity` is untouched. That is the resolution of the tension with Tier 1C, whose T1-7/T1-8 mandated these lines for cross-examination survivability — the archive keeps the full record, the reading copy goes lean.

## Verified against 757d972 — trust these over the spec where they disagree

- **The model name is not its own line.** `MetadataFormat.cs:39-42` joins version, model and backend with `\u00B7`. Deleting the model means deleting `Transcript version` entirely. It is emitted **unconditionally** — no null guard, unlike every other provenance line.
- **Part 1 changed this area.** Imports now seal their audio (`OfflinePipelineRunner.cs:244`, `AudioImporter.cs:339/566` pass `sealAudio: true`), so an imported session today prints `Audio: x.mp4`, `Audio SHA-256: <source>` **and** `Audio SHA-256 (local.flac): …`. The doc comment at `ExportProvenance.cs:98-100` claiming per-leg lines are empty for imports is now **stale**. The spec's §3.1 inventory implicitly treats per-leg lines as recorded-only; that is wrong post-Part-1.
- **Part 1 also added `AppendEngine`** to `MarkdownRenderer.cs` and `PlainTextRenderer.cs` so a salvaged session with empty `Model`/`Backend` does not render a bare `/`. Part 3 removes the engine from the header anyway — check whether `AppendEngine` becomes dead, and note the save-time `transcript.md`/`.txt` one-line header is a *different* surface that is OUT of scope.
- **Salvaged sessions exist now.** A failed import keeps its session with `Model = ""`, `Backend = ""`, `WeightsFile = null`. Several fields Part 3 deletes are already empty on that path.

## Traps that will cost you a day each

1. **The `Excerpt:` line is already ordered differently across renderers** — docx emits it *after* the in-progress notice (`DocxRenderer.cs:85-90`), md/txt emit it *before* (`MarkdownRenderer.cs:91`, `PlainTextRenderer.cs:92`). Predates this work. A "all three must match" golden test fails on day one. Preserve the asymmetry or fix it deliberately; existing tests pin the md/txt position.
2. **Docx emits the in-progress and excerpt notices TWICE** — body block *and* the running page header part (`DocxRenderer.cs:165-170`). Trimming only the body leaves them on pages 2+.
3. **Deleting the corrected mark is not one line in docx.** `DocxRenderer.CorrectedMark` (`:294-295`) is called at `:304` for the label suffix **and** at `:122`, where the continuation suffix composes `CorrectedMark(...) + " (cont'd):"`.
4. **A WPF binding to a deleted property fails silently at runtime**, not at build. `ExportDialog.xaml:64` must be deleted by hand — nothing in the 2587-test suite catches leaving it.
5. **`DisplayRow.HasCorrection` does NOT become dead.** `ReadViewWindow.xaml:571` binds it for the read-view per-row indicator. Deleting it removes a UI feature.
6. **`HumanLayerCounts` must survive** the removal of the `Human edits` line — the new `Omitted:` line reads `SuppressedDuplicates` from it, and the disclaimer variant is chosen from it. Only `MetadataFormat.HumanLayerLine` goes.
7. **`session.txt` is OUT of scope** but contains `Participants:` too (`RendererTests.cs:89`, `SessionProjectionLoaderTests.cs:73`). A repo-wide search-and-replace will break it.
8. **No settings migration is needed.** `ExportSetting.MarkCorrectedTurns` was added additively with no schema bump; `SettingsStore.Version` stays 3 and a stale key is ignored on deserialize, dropped on next save. The spec's "settings migration drops the key" is wrong — there is nothing to migrate.
9. **`DocxRendererTests.cs:679`** asserts `DoesNotContain("Audio:")` for a recorded session. Under decision 2 that premise still holds, but re-read it rather than assuming.

## Non-negotiables on this repo

- **ASCII source only.** Non-ASCII in `src/` must be `\uXXXX` escapes — a byte-scan gate fails the build.
- **Gate:** `dotnet test LocalScribe.slnx --filter "Category!=Fixture"` — 2587 tests, ~65 s. Never `--no-build` from a stale tree.
- **Also run the gate with `LOCALSCRIBE_MODELS` pointed at a fresh empty directory.** This is a standing criterion added during Part 1 after two defects that passed only because this machine holds every ladder rung. CI fetches no models.
- Don't run `LocalScribe.App.exe` while building — it locks `Core.dll` (MSB3027).
- Branch off `master`; do not work on `master` directly.
